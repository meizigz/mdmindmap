# 行内解析

Status: resolved
Blocked by: 01
Spec: [spec.md](../spec.md) §3、§4，附录 A「转义与行内规则」

## 要做什么

- 手写行内解析，产出不依赖 DOM 的 `Inline[]` 结构。只认 §3 的固定子集，其余写法原样当作文字。
- 优先级：代码和公式最先识别（里面的内容当原文），其次是双链和链接，最后是粗体、斜体、删除线、高亮。
- `$` 的判定与 Obsidian 一致（§4）。反斜杠可以转义 markdown 标点。
- 从 `mdmindmap/parse` 导出，并在块级解析中填入 `Node.inline`。如果「块级解析」还没合并，先做成独立的函数。

## 验收

- 单元测试覆盖：嵌套（粗体里有公式）、未闭合的标记、`$5 and $6` 这类不算公式的写法、`[[a|b]]`、HTML 标签原样显示。
- `npm run check` 通过。

**2026-10-03 完成**（Claude）。`src/parse/inline.ts`，从 `mdmindmap/parse` 导出 `parseInline`；块级解析已经用它填入 `Node.inline`。共 15 条单元测试，覆盖验收要求的全部情况，`npm run check` 通过。

**`Inline` 的结构**（spec §4 引用的类型，渲染器要按它构造 DOM）：
`text` · `strong` / `em` / `del` / `mark`（带 `children`）· `code`（`text`）· `math`（`tex`）· `wikilink`（`target`，可选 `alias`）· `link`（`href`、`children`）。

**实现中做出的选择**：
- **强调的配对**：只要求开符号后面、闭符号前面不是空白，**不用** CommonMark 的标点侧翼规则（它在中文里会失效，例如 `**“引号”**后`）。`***x***` 解析为斜体包粗体，与 CommonMark 一致。`~~` 和 `==` 必须恰好两个。
- **下划线 `_` 不是强调**（spec 的子集里没有它），这样 `F_合` 之类不会误判。
- **`$$…$$` 也当作行内公式**。spec 只列了 `$…$`，但 `$$` 的意图明确，Obsidian 也会渲染；照原样显示反而难看。写作说明里仍然要求不要用它。
- **公式里的 `\$` 不算结尾**。`$a $b$` 中第一个候选的结尾 `$` 不合规则，会继续往后找，结果是公式 `a $b`（与 Pandoc 一致）。
- **图片和嵌入**（`![alt](src)`、`![[文件]]`）、脚注 `[^1]`、HTML 标签都原样显示。链接文字里不再识别链接和双链。
- **反斜杠**只转义 ASCII 标点；`a\b` 保持原样。
