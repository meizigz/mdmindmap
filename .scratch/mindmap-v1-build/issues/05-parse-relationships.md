# 联系区解析与诊断

Status: resolved
Blocked by: 02
Spec: [spec.md](../spec.md) 附录 A「联系区」、§5

## 要做什么

- 识别源文末尾的 `%% … %%` 联系区，解析 `a -->|标签| b`、`-.->`、`==>`。端点是裸ID。
- 产出 `Relationship[]`。
- 诊断：
  - `REL_UNKNOWN_ID`：端点恰好是某个节点的文字时，提示给该节点加 `^id`；与已有ID只差几个字母时，提示「是不是 `xxx`？」。
  - `REL_SELF`。
  - `REL_UNPARSED`：箭头写成 `->` 时专门指出。
  - `REGION_UNCLOSED`、`REGION_NOT_LAST`、`REL_OUTSIDE_REGION`。

## 验收

- 每个 code 都有最小样例和快照。
- 端点带 `^` 时，给出合理的诊断（不能静默接受），并在 `fix` 里说明要去掉 `^`。
- `npm run check` 通过。

**为了让行为确定而做的选择**：

- **哪个 `%%` 块是联系区**：单独一行 `%%` 开始、单独一行 `%%` 结束的块，如果它后面只剩空行，就是联系区。块里的每一行都按联系解析，看不懂的报 `REL_UNPARSED`。
  - 不在最后、但写了联系的块：
    - 代码块模式：照常认作联系区，报 `REGION_NOT_LAST`（报在后面第一行内容上），后面的内容都忽略。
    - 整篇模式：当作普通注释，也报 `REGION_NOT_LAST`（报在块的第一行上），里面的联系不画。
  - 不在最后、也没写联系的块：普通注释，静默跳过。
  - 整行都是 `%%注释%%` 的行：静默跳过，两种模式都一样。
  - **整篇模式的说明**：整篇模式下，联系区必须是最后一个块，这条规则在这里已经实现了。「整篇模式」工单还要补一件事：让 `%%` 块的识别跳过围栏代码块里的 `%%`。
- **`%%` 块和 frontmatter 里的行**：当作空行处理，所以会打断续行。
- **`REL_OUTSIDE_REGION`**：只在一整行恰好是「ID 箭头 ID」的形状时报，例如 `a --> b`。正文里夹着箭头的普通句子不报。
- **端点带 `^`**：报 `REL_UNKNOWN_ID`，不画这条联系。`fix` 会说明去掉 `^`；如果去掉后的ID也不存在，会一并指出。
- **编辑距离提示**：距离 ≤ 2、且小于ID长度时，提示「是不是 `xxx`？」。
- **空标签** `-.->| |`：视为没有标签。
- **箭头写错**：没有用后行断言（spec §12 的 iOS 限制）。会识别 `->`、`=>`、`-.>`、`<--`、`<-`、`<==`、`---`、`--`、`==`、`→`、`⟶`、`⇒`。
