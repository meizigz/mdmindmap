# 整篇模式解析规则

Status: resolved
Blocked by: 02, 05
Spec: [spec.md](../spec.md) 附录 A「整篇模式的额外规则」、§4

## 要做什么

- 调用 `parse(source, { document: { title } })` 时进入整篇模式：
  - 非节点内容（段落、表格、callout、分隔线，以及整块的代码块，包括 `mdmindmap` 代码块）静默跳过，不报 `NON_NODE_LINE`。
  - 根节点：恰好只有一个一级标题、且其他节点都在它下面时，它就是根；否则用 `title` 作根。
  - 只有文件的最后一个块是 `%% … %%` 时，它才是联系区；正文中间的 `%%` 块一律跳过。
  - 诊断：`ID_NOT_LAST`（hint）。

## 验收

- 快照覆盖：多个一级标题；没有标题；正文中夹着代码块（块里的 `#`、`-` 不成为节点）；正文中间的 `%%` 注释。
- `npm run check` 通过。

## Comments

**2026-10-03 完成**（Claude）。样例在 `fixtures/document/*.doc.md` 下，另有 `fixtures/diagnostics/ID_NOT_LAST*.md`。`npm run check` 通过。

- **非节点内容的跳过**：
  - 段落、表格、callout、分隔线、图片嵌入，以及隔着空行的缩进段落，在整篇模式下本来就不报警告（`reportNonNodeLines` 关闭）。
  - 新增 `blockLines()`，把下面几种块**整块**跳过，块里的 `#`、`-`、`%%` 都不算数：
    - 围栏代码块（`` ``` `` 和 `~~~`，闭合围栏不能比开头短）
    - 嵌入的 `mdmindmap` 代码块
    - 没有闭合的围栏，一直延续到文件末尾
    - **独占一行的 `$$` 公式块**：spec 没有单独列出这一项，但块里以 `-` 开头的行会被误当成节点，所以一并跳过。
  - 识别 `%%` 块时也会跳过这些行。
- **根节点**：全文恰好只有一个一级标题、而且它是第一个节点时，它就是根。否则用文件名生成一个根节点，`line` 为 **0**，表示没有对应的源文行，spec §4 已同步更新。宿主跳转源码时，要把 0 当作「不跳转」或「跳到文件开头」。所有顶层节点都挂在它下面，不报 `MULTI_ROOT`。
- **`NO_NODES`**：整篇模式下，如果一个标题或列表项都没有（例如只有段落），根节点为 `null`，并报 `NO_NODES`，不会只显示一个文件名节点。
- **`ID_NOT_LAST`**：只在整篇模式下报，hint 级别。
- **已知限制**：不支持 setext 标题（文字下一行写 `===` 或 `---`）。这种写法会被当作普通段落和分隔线跳过。AI 和写作说明都不用这种写法。
