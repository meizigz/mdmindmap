## 要做什么

- 依赖 `@plait/layouts` 0.94.1（锁定版本），并包在自己的接口后面。输入：解析树、每个节点的尺寸、结构；输出：每个节点和每个概要括号的坐标。
- 概要按 `{ start, end }` 节点追加到父节点 `children` 的末尾。
- bilateral 结构：用 `rightNodeCount` 决定右侧有几个分支，切分点不能落在任何概要的范围内部；暂时按子树节点数均分。
- 折叠的子树不参与排版。

## Comments

**2026-10-03 完成**（Claude）。`src/layout/index.ts`，依赖 `@plait/layouts`，**锁定为 0.94.1**。在 Node 里用假尺寸测试，共 13 条，`npm run check` 通过（全仓库 189 条测试）。

**接口**（内部模块，不对外公开）：
- `layoutTree({ root, layout, size, underline, collapsed })` 返回：
  - `boxes: Map<Node, Box>`：只包含可见节点；`Box` 有 `x`、`y`、`width`、`height`，以及 `left`（是否在根节点左侧）。
  - `braces`：每个概要括号的 `top`、`bottom`、`x`（括号贴着的那一侧：右侧括号取子树最右边，左侧取最左边）和 `left`，括号曲线由渲染器自己画。
  - `bounds`：整张图的边界。
- `chooseRightCount(root, collapsed)`：bilateral 结构下右侧放几个一级分支。

**发现并采用的能力：下划线对齐**。`@plait/layouts` 支持 `ConnectingPosition.bottom`。对下划线式节点打开它后，父节点的下划线会对齐到首尾两个子节点下划线的中间，和 XMind 一样。原型没有用它。渲染器要把「二级及更深、没有颜色、不是概要」的节点作为 `underline` 传进来，「渲染流水线」工单要照此实现。测试从正反两个方向验证了这一点：打开时偏差小于 1 px，关闭时（按中线对齐）偏差大于 5 px。

**几何测试覆盖的情况**：
- 参考截图那张图；概要带多层子节点（牛顿样例）；相邻概要；概要的子节点里再套概要。
- bilateral 左侧分支上的概要（括号朝左）；根节点上的概要不会被切到两边；长短悬殊的节点。
- 折叠后代不参与排版；`chooseRightCount` 均分、不切开概要、折叠的子树只算一个节点。
- 每个情况都检查这些不变量：盒子两两不重叠；子节点在父节点正确的一侧；概要节点在它括住的子树之外；括号覆盖住被括的兄弟；被括的兄弟和括号在同一侧；所有可见节点都排进去了。

**间距**沿用原型调好的值：水平方向根节点 30、一级 22、更深 16、概要 20；垂直方向一级 9、更深 4。目前是模块内的常量，之后如果要跟随字号变化，再改成参数。
