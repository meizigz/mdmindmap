# 平移缩放、点击激活与折叠

Status: resolved
Blocked by: 10
Spec: [spec.md](../spec.md) §6、§8

## 要做什么

- 平移缩放：滚轮缩放，拖动或单指平移，双指缩放；`fit()`。
- `interaction`：
  - `click-to-activate`：激活前不拦截滚轮和触摸，点一下导图后激活；点外面、按 Esc，或可见部分不足 30% 时退出激活。
  - `direct`：始终可以操作。
- 折叠：
  - 节点上有折叠按钮，折叠后按钮显示子节点数。
  - 源文中的 `<!-- fold -->` 决定默认折叠哪些节点。
  - `collapseAll(depth?)`。
  - 折叠后，被点的节点在屏幕上原地不动。
- `height: 'auto'`：按 §8 的公式同步算好高度；导图底边可以拖动调整高度。

## 验收

- 浏览器模式测试：折叠前后，被点节点的屏幕坐标不变；自动高度符合公式和上下限。
- 手动：在电脑 Chrome 和安卓 Chrome 的演示页中，两种交互模式都能用。
- `npm run check` 通过。

**结构**：
- `src/render/viewport.ts`：视口，负责平移、缩放、轻点和点击激活。
- `src/render/index.ts`：改成以 `refresh({ initial?, anchor? })` 为核心。元素和尺寸都有缓存，折叠或展开时只测量新出现的节点。刷新会排队执行，连续点击不会让测量交错。

**实现中做出的决定**（spec §6、§8 已同步更新）：
- **`interaction` 的默认值**：给了 `height`（嵌在页面或笔记里）时为 `click-to-activate`，否则为 `direct`。
- **`height`**：不给时占满容器的高度。给数字就用该高度；给 `"auto"` 时按公式估算，在构造函数里同步算好。给了 height 才有底边拖动手柄。
- **首次显示**：能以不低于 60% 的缩放放下整张图就 fit；否则按 60% 显示，根节点靠左（bilateral 时居中）、上下居中。原因是三角函数那张大图 fit 后只有约 35%，字完全看不清。`fit()` 本身不受这个下限影响，最小可以到 10%。
- **`collapseAll(depth = 1)`**：折叠深度不小于 depth 的节点，展开比它浅的节点，然后 fit。返回 Promise。
- **点击激活的细节**：
  - 激活前不处理指针和滚轮（`touch-action` 保持默认，页面可以正常滚动和缩放）。轻点只负责激活，不会触发折叠或点击链接；随后浏览器派发的 click 也会被吞掉。
  - 激活后，导图边缘会显示一圈强调色描边作为提示。
  - 点导图外面（document 上的 capture 阶段 pointerdown）、按 Esc、或可见部分不足 30%（IntersectionObserver）时退出。
- **拖动与轻点**：移动超过 4px 才算拖动；拖动结束后不触发折叠或点击。双指捏合时以两指中点为中心缩放，同时跟随平移。滚轮的灵敏度：普通滚轮 0.0015，触控板捏合（ctrlKey）0.01。缩放范围 10%–400%。
- **指针捕获**：`setPointerCapture` 在指针已经抬起或不是真实指针时会抛错，统一用不会抛错的 `capture()`。
- **折叠按钮**：位置在分支出发点；折叠时显示被折叠后代的总数（含概要节点）。展开状态平时隐藏、悬停时显示，触屏设备上一直显示。它不是 `<button>`（Obsidian 主题会给全局按钮加样式），而是 `div[role=button]`，带 `aria-expanded`。
