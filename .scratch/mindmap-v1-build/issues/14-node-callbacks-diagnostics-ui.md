# 节点回调、链接与诊断角标

Status: resolved
Blocked by: 10
Spec: [spec.md](../spec.md) §5、§6、§8

## 要做什么

- `onNodeClick(node)`，`node` 带 `line`。
- `onLinkClick(target, event)`：没传时，双链只显示样式、不可点击。外部链接在新窗口打开。
- `onNodeMenu(node, position)`：右键，或长按 550 ms 时触发。安卓上长按会同时触发系统的 `contextmenu`，要防止菜单弹出两次。
- 诊断：
  - 提供 `mm.diagnostics` 和 `onDiagnostics`。
  - 有问题时，角落显示「⚠ N」，点开列出问题。
  - 点列表中的某一条，触发跳转回调，与节点点击的跳转相同。回调签名由实现决定，并补进 spec §6。
  - 一个节点都没有时，显示错误面板。

## 验收

- 浏览器模式测试：点击和右键会触发对应的回调；含错误的源文能显示角标和问题列表。
- `npm run check` 通过。

## Comments

**2026-10-03 完成**（Claude）。共 11 条浏览器测试，全仓库 `npm run check` 通过（235 条测试）。验收已满足：点击和右键都会触发对应的回调；有错误的源文会显示角标和问题列表。

**诊断列表里点某一条时的回调签名**（工单要求在这里决定并补进 spec §6）：新增选项 `onDiagnosticClick?: (diagnostic: Diagnostic) => void`。宿主用 `diagnostic.line` 跳到源码；代码块模式下要自己加上围栏所在的行号。没传这个选项时，列表只用来看。

**实现中做出的决定**：
- **轻点的优先级**：折叠按钮 → 双链（有 `onLinkClick` 时）→ 外部链接（交给浏览器在新窗口打开）→ 节点（`onNodeClick`）。点双链或外链时，不会同时触发节点点击。没传 `onLinkClick` 时，双链就是节点文字的一部分，点它等于点节点；`.mdmm` 上没有 `data-links`，因此光标不变。
- **节点菜单**：
  - 右键在导图已激活时才拦截（`click-to-activate` 激活前，右键仍是浏览器或宿主自己的菜单）。没传 `onNodeMenu` 时不拦截。
  - 触屏长按 550 ms 弹出菜单；1 秒内随后到达的系统 `contextmenu` 会被吞掉（安卓的双重触发）；长按后的抬起不算轻点。长按只在非鼠标指针、导图已激活、单指时生效；移动超过 4px 或第二根手指落下都会取消。
- **`onDiagnostics`**：用 `queueMicrotask` 在 `render()` 返回之后调用一次，这样回调里已经能拿到返回的实例。
- **角标与列表**：
  - 角标显示错误和警告的条数，颜色取最严重的级别；hint 只出现在列表里，单独有 hint 时不显示角标（避免整篇模式下 `ID_NOT_LAST` 常驻一个角标）。
  - 点角标打开或收起列表；列表里的文字可以选中复制。条目显示「第 N 行」（行号相对源文）、信息和改法。
  - 一个节点都没有时，列表铺满画布、默认展开，不显示角标。
- **跨窗口**：事件目标改用鸭子类型判断（看有没有 `closest`），因为 `instanceof Element` 在 Obsidian 的弹出窗口里不可靠。定时器用节点所在窗口的 `setTimeout`。
- 「第 N 行」这类界面文字目前写死为中文，和诊断信息保持一致。Obsidian 插件的中英界面文字只覆盖插件自己的命令和菜单。
