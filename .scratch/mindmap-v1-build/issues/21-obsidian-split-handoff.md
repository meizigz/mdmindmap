# Obsidian：分屏编辑时保持状态与跟随编辑

Status: claimed
Blocked by: 16, 18
Spec: [spec.md](../spec.md) §12「分屏编辑时保持状态」

## 要做什么

- 交接池：
  - 旧的代码块元素卸载时，把导图放进池中，保留 2 秒。
  - 新元素挂上页面后，按「同一分屏、同一文件、第几个 `mdmindmap` 代码块」找回旧实例，把它的 DOM 移过来，再调用 `update(source)`。
  - 找不到时新建实例。
- 跟随编辑：被编辑的行落在另一个分屏的某张导图里，而对应节点不在视野内时，用最小的平移把它移进视野，并短暂高亮。

## 验收

- **需要用户在 Obsidian 中实测**（电脑 + 安卓）：一边编辑一边看另一个分屏中的导图：没有闪烁，缩放不复位，正在编辑的节点始终可见。
- `npm run check` 通过。

## Comments

**2026-10-03 代码完成，等待用户在 Obsidian 中实测**（Claude）。

**插件**（`src/block.ts`、`src/main.ts`）：
- **交接池**（插件级的 `BlockRegistry`）：
  - 代码块组件卸载时，不销毁导图，而是放进池中，2 秒后再销毁。
  - 新组件等元素挂进页面后（最多等 30 帧），按「同一分屏（`.workspace-leaf` 元素）、同一文件、第几个 mdmindmap 代码块」找池里的旧实例。找到就把旧的外层元素移过来，重新绑定 DOM 事件，再调用 `update(source)`；找不到就新建。
  - 导图的回调通过一个可以改指向的 `owner` 对象转发给「当前负责它的组件」，所以接手后跳转源码、菜单、双链都用新组件的 `ctx` 和元素。
  - 插件卸载时，销毁池里所有导图并清掉定时器。定时器记下了设定它的窗口，以兼容弹出窗口。
- **跟随编辑**：
  - 插件监听 `editor-change`，记下文件、光标所在行和编辑器所在的分屏，然后通知所有活着的代码块。
  - 代码块判断：同一文件、不在同一个分屏、编辑的行落在自己的围栏之间、编辑发生在 5 秒内，满足时才调用 `map.revealLine(行, { flash: "moved" })`。
  - 接手旧实例、`update()` 完成后也会再判断一次，因为编辑本身会让另一个分屏的代码块重新渲染。

**核心库的配套改动**（spec §6 已补上 `revealLine`）：
- `mm.revealLine(line, { flash? })`：
  - 找到源文第 line 行对应的节点。这一行不是节点行时（例如续行），取它上方最近的节点；节点被折叠时，取最近的可见祖先。
  - 用最小的平移把它移进视野（四边留 24px），缩放不变。
  - 高亮：用 outline 动画，不碰预设颜色用的 box-shadow。`flash: "moved"` 时只有真的平移了才高亮，免得每敲一个字都闪一下。
- **等挂进页面再测量**：Obsidian 可能先给一个还没挂进页面的元素，这时量出来的尺寸都是 0。核心库在测量前会逐帧等待，直到元素挂上（或实例被销毁）。web 端同样受益。
- 新增 4 条浏览器测试：远处节点移进视野；已在视野中不平移；折叠里的节点取祖先；容器后挂上也能正确测量。

**待实测**：一边编辑一边看另一个分屏中的导图，没有闪烁，缩放不复位，正在编辑的节点始终可见。
