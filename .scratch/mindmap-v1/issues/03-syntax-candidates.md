## Question

在 markmap 兼容的「标题 + 列表」基础上，**概要**、**节点ID**、**联系区域**、**节点颜色**（以及可选的默认折叠）用什么标记写？

做 2–3 套候选语法，每套都把样例截图那张导图完整写出来，并对比：
- 在纯 markdown 预览 / Obsidian 阅读视图里（未装插件时）看起来是否只是轻微噪音
- 手写是否顺手、是否容易出错（例如概要范围怎么标定相邻兄弟）
- 与 markmap 现有写法、mermaid 联系写法的一致性
- 解析是否无歧义

已知约束（来自「Obsidian 插件 API 对本需求的支持情况」）：节点ID 只能用 `[A-Za-z0-9-]`；整篇文件模式下列表项末尾的 `^id` 会成为真正的 Obsidian 块ID（可被外部引用，算加分项）；标题行末 `^id` 行为未验证；`mindmap` 代码块名已被其他插件占用，需可配置或另起名。

可参考的现成写法：mind-elixir plaintext 格式（`[^id]` 节点ID、`}:2` 概要括住前 2 个兄弟、`> [^a] >-label-> [^b]` 联系）可作为候选之一。

产出：选定一套语法，形成语法规格草案。

## Answer

与 pengyg 逐项选定（候选 A/B/C 见原型），规格见 [syntax-spec.md](../syntax-spec.md)：

- **概要**：列表项 `- } 文字`，写在被括兄弟之后，默认括住「上一个概要之后」的全部兄弟；只括中间一段时，在起点兄弟行首加 `{ `。不计数。原型显示：计数写法 `}:N` 在范围末尾加兄弟时会悄悄漏掉第一个；只有 `}` 的写法在范围前插入兄弟时会悄悄多括一个；`{` 不用数数就能修好。
- **节点ID**：行尾 `^id`，只允许 `[A-Za-z0-9-]`（不允许中文，保留整篇文件模式下真块ID的好处），写错时报错。
- **颜色**：行尾色块 emoji（🔴🟠🟡🟢🔵🟣⚫ 对应 7 个预设色）。没装插件时也能看出颜色。
- **默认折叠**：`<!-- fold -->`，同时接受 markmap 的 `<!-- markmap: fold -->`。
- **联系区**：源文末尾的 `%%` … `%%` 注释块，每行 `a -.->|标签| b`，**端点用裸ID**。原型发现：联系行尾写 `^b` 会让 Obsidian 把它当成这一行自己的块ID，与节点的 `^b` 冲突。Obsidian 阅读视图里整个联系区被隐藏。
- **代码块名**：`mdmindmap`（`mindmap` 已被占用）。
- 后续：转义与报错呈现交给「解析器选型与语法错误提示」。

## 后续修订

- 2026-10-03：主要写作方式改为「AI 先生成，人工微调」（见地图 Notes）。概要规则不变，但**标准写法定为成对的 `{ … }`**，单独的 `}` 仍然合法。之后「AI 生成实测与写作说明」可能进一步修订本工单的其他决定，每一项都要经用户同意。
- 2026-10-03：「AI 生成实测与写作说明」显示，弱模型说明里点名之后仍会把 `^id` 写在 `<!-- fold -->` 前面。因此行尾标记改为**顺序任意**：只在整篇文件模式下，`^id` 不在最后时给提示（这时它不是 Obsidian 块ID）。其他决定经实测确认，不改。
