## Question

`mdmindmap` 代码块嵌在笔记里时，导图的交互怎么做，才不会与笔记本身冲突？

- **滚轮**：滚轮是滚动笔记还是缩放导图？对应 API 的 `wheel: 'zoom' | 'modifier' | 'none'`，各视图的默认值是什么？触控板的双指缩放和滚动怎么区分？
- **触摸**（安卓）：单指在导图上滑动，是平移导图还是滚动笔记？双指缩放会不会和页面缩放冲突？
- **点击**：实时预览中点击导图会不会把光标放进代码块，导致导图被替换成源码（见「Obsidian 插件 API 对本需求的支持情况」第 1 项）？点击节点跳转源码、点击折叠按钮、点击双链，各自如何避开这个问题？
- **代码块默认高度**：Obsidian 的代码块高度完全由插件决定，而且要同步确定以免页面跳动。按节点数或深度估算、固定高度、还是允许写参数（比如围栏后加 `height=400`）？能不能拖动调整？
- **复制节点文字**：画布上已经禁止选中文字（见「排版引擎与节点渲染原型验证」约束 4），还要不要提供复制（比如右键或长按菜单「复制节点文字」）？
- 有没有「全屏/在新标签页打开这张导图」的入口，用来查看大图？

做法：写一个最小的 Obsidian 原型插件，把「排版引擎与节点渲染原型验证」的渲染流水线（分支 `prototype/layout-render-spike`）接进代码块处理器，在电脑和安卓上的阅读视图和实时预览里实测。产出：各项交互的规则，以及 `render()` 选项中需要补充或调整的部分。

## Context

- 原型插件：分支 `prototype/obsidian-interaction-spike` 的 `prototypes/obsidian-spike/`（commit f8818bc；分屏编辑的修复在 85589f1）。`npm i && npm run build` 会打包并装进测试库，同时写入测试笔记。每张导图下方的切换栏可切换交互变体（A 直接操作 / B 修饰键 / C 点击激活）和高度方式（自动估算 / 固定 / 围栏参数）；状态行实时显示每次交互被如何处理。

## Answer

pengyg 在电脑和安卓上、阅读视图和实时预览里实测确认。

1. **交互采用 C「点击激活」**：嵌在笔记里的导图默认不响应滚轮和拖动，滚轮和手指滑动都照常滚动笔记。点一下（轻点一下）导图后才能平移、缩放、折叠、点节点，行为同「直接操作」：滚轮缩放，拖动或单指平移，双指缩放。点导图外面、按 Esc、或导图滚出屏幕（可见部分不足 30%）时退出。在「新标签页打开」的全屏视图里始终直接操作。另外两种被否决：A「直接操作」会抢走笔记的滚动；B「修饰键」在触摸屏上要区分横竖滑动，不直观。
2. **防止实时预览把导图换成源码**：在整个导图部件上拦截 `mousedown`、`pointerdown`、`click`、`dblclick` 的冒泡，包括导图外围的工具栏，不只是画布。实测有效：漏掉外围工具栏时，点它会让光标进入代码块。
3. **默认高度用「自动估算」**：渲染前同步算好，避免页面跳动。高度 = 可见叶子数 × 26 + 40，限制在 220–600 px，折叠的分支不计入。另外支持可选的围栏参数 `` ```mdmindmap height=500 `` 覆盖（已写进规格），导图底边可以拖动调整高度（不写回源文）。
4. **点节点跳转源码**：先切到编辑模式，调用 `view.setEphemeralState({ line })` 让 Obsidian 滚到那一行，等一帧再 `setCursor` 加居中的 `scrollIntoView`。只用 `scrollIntoView` 时，源码很长的话目标行会停在屏幕外（实测出现过）。文件行 = 代码块围栏所在行 + 节点在源文中的行号。
5. **复制节点文字**（画布禁止选中文字的替代办法）：右键或长按（550 ms）节点弹出 Obsidian 菜单，含「复制节点文字」「跳到源码」「复制块引用」（仅整篇模式有效）。实测可用。安卓长按会同时触发计时器和系统 `contextmenu`，要防止菜单重复弹出。
6. **「新标签页打开」**：导图右上角的按钮用自定义 `ItemView` 在新标签页里全屏显示这张导图，方便看大图。原型里已实现；用户的反馈集中在前几项，没有单独评价这一项。
7. **公式**：在插件里用 Obsidian 的 `renderMath` 加 `finishRenderMath`，然后测量，节点尺寸正常。
8. **分屏编辑时保持导图状态**（用户追加的问题，已修复并实测）：在分屏 1 编辑时，Obsidian 会让分屏 2 的代码块处理器重新执行，起初导图被整张重建，于是缩放复位、画面闪烁。解法：
   - **接手旧实例，而不是重建**。旧代码块元素卸载时，不立刻销毁导图，而是放进交接池 2 秒。新元素挂进页面后，找到「同一分屏、同一文件、第几个 `mdmindmap` 代码块」都相同的旧实例，把它的 DOM 移过来，调用 `update(source)`。
   - **`update()` 是增量的**：路径和文字都没变的节点直接复用元素和尺寸，只测量新的或改过的节点；新画面画好之前旧画面一直留着；更新后按离视口中心最近的节点重新对齐视口，缩放不变；折叠状态按节点路径保留。
   - **跟随编辑**：监听 `editor-change`；被编辑的行落在另一个分屏的某张导图里、而对应节点不在视野内时，最少地平移把它移进来，并短暂高亮。
   - 找不到旧实例时（比如第一次打开），退回「新建实例 + 按记录恢复视口」。
   - 实测：不再闪烁、不再复位。输入很长的内容时，位置会有点偏：对齐用的是节点左上角，节点变宽变高后会漂移。实现时改用节点左侧中点，或固定被编辑的节点。
9. **对 API 的修订**（「包拆分与对外 API」）：`wheel` 选项改为 `interaction: 'click-to-activate' | 'direct'`，嵌入时默认 `click-to-activate`，独立视图默认 `direct`；新增 `height?: number | 'auto'`，以及 `onNodeMenu?: (node, position) => void`，由宿主弹出自己的菜单。
