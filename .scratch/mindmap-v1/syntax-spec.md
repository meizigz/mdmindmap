# 源文语法规格（草案）

来源：「[扩展语法候选方案对比](issues/03-syntax-candidates.md)」。术语见 [CONTEXT.md](../../CONTEXT.md)。

## 源文形态

- **代码块**：围栏语言名 `mdmindmap`（`mindmap` 已被 Markdown Mindmap、Mindmap Blocks 两个插件占用）。围栏行可选写高度：`` ```mdmindmap height=500 ``；不写时按叶子数自动估算（见「[实时预览与阅读视图中的交互和代码块尺寸](issues/10-live-preview-interaction.md)」）。
- **整篇 `.md`**：任何 `.md` 文件都可以作为源文，不需要声明（打开方式见「[整篇 .md 作为导图的识别与打开方式](issues/05-whole-file-mode.md)」）。开头的 YAML frontmatter 不参与解析。另有三条规则只适用于整篇模式，见下文「整篇模式的额外规则」。

## 节点（与 markmap 兼容）

- ATX 标题（`#` … `######`）和列表项（`-` `*` `+` `1.`）都是节点。标题按级别成层；列表项挂在它上方最近的标题下，按缩进嵌套。
- 只有一个根：第一个最浅层的节点。之后再出现同层的顶层节点 → 报错。（整篇模式另有规则。）
- 列表项的**续行**（紧跟在列表项后、没有空行隔开的缩进行）属于同一个节点，用空格并进节点文字。
- 既不是标题也不是列表项的非空行不成为节点 → 代码块模式下给出警告并忽略（整篇模式下静默跳过）。
- 节点文字里的行内 `%%…%%` 注释会被去掉。
- 节点文字支持的行内写法（固定子集，由核心库解析，见「[包拆分与对外 API](issues/06-packages-and-api.md)」）：`**粗体**`、`*斜体*`、`~~删除线~~`、`` `代码` ``、`==高亮==`、`[[双链]]` / `[[双链|显示文字]]`、`[文字](网址)`、行内公式 `$…$`（含 mhchem `\ce{}`）。其余写法（HTML 标签、图片、脚注等）原样显示为文字，不报错。

## 行尾标记

一行的完整形态：`内容 [颜色] [折叠] [^id]`。三种标记的**顺序任意**，都能正常解析（来自「[AI 生成实测与写作说明](issues/09-ai-generation-trial.md)」）。推荐把 `^id` 放在最后：整篇文件模式下，只有在行尾的 `^id` 才是真正的 Obsidian 块ID；不在最后时给一条提示（「这个ID无法被外部引用」），不算错误。

| 元素 | 写法 | 规则 |
|---|---|---|
| 节点ID | ` ^law2` | 只能用 `[A-Za-z0-9-]`，全文唯一。行尾的 `^token` 只有符合这个字符集时才算节点ID，否则照常作为内容（例如 mhchem 用 ` ^` 表示生成气体：`$\ce{… + H2 ^}$`）；看起来像是想写ID、却用了非法字符（如 `^期望`）时，给出提示。整篇文件模式里它就是真正的 Obsidian 块ID（阅读视图隐藏，可被 `[[文件#^law2]]` 引用）。只在列表项上使用；标题行尾的 `^id` 在 Obsidian 里不是块ID。 |
| 颜色 | 行尾色块 emoji | 🔴 red · 🟠 orange · 🟡 yellow · 🟢 green · 🔵 blue · 🟣 purple · ⚫ gray。只认这 7 个，且只认行尾那一个。 |
| 默认折叠 | `<!-- fold -->` | 也接受 markmap 的 `<!-- markmap: fold -->`。所有 markdown 预览里都隐藏。 |

## 概要

- 概要写成一个**列表项**，文字以 `} ` 开头，放在它括住的那些兄弟**之后**，缩进与这些兄弟相同。
- **默认范围**：从同一父节点下上一个概要之后的第一个兄弟（若没有上一个概要，则从第一个兄弟起），到紧挨在 `}` 前面的那个兄弟。
- **显式起点**：在起点兄弟的文字前加 `{ `，范围就从这个兄弟开始，到 `}` 之前为止。范围起点就是默认起点时，`{` 可以省略。
- **标准写法是成对的 `{ … }`**：起点兄弟前写 `{ `，即使它就是默认起点也写。写作说明和文档中的样例一律用成对写法，AI 也只按成对写；单独的 `}` 仍然合法，留给人手改时省事。
- 概要本身不算兄弟，不计入任何范围。概要节点的子节点照常缩进写在它下面；概要也可以带颜色、折叠、`^id`。
- 按这种写法，概要之间天然不会重叠、不会嵌套。
- 报错：`}` 前面没有可括的兄弟；`{` 没有对应的 `}`；同一父节点下出现两个未闭合的 `{`。

## 联系区

- 位于源文末尾，是一个 Obsidian 注释块：单独一行 `%%` 开始，单独一行 `%%` 结束。之后不应再有内容。每份源文最多一个；没有联系时省略。
- 每行一条：`起点 箭头 终点`，或带标签 `起点 箭头|标签| 终点`。
- 箭头：`-->` 实线，`-.->` 虚线，`==>` 粗线（mermaid 子集）。
- 端点写**裸节点ID**，不带 `^`。如果带 `^`，行尾的 `^id` 会被 Obsidian 当成这一行自己的块ID，与节点上的同名 ID 冲突（原型已证实这种冲突会出现在列表项上）。
- 起点和终点不能是同一个节点 → 报错，这一条不画。
- 起点或终点的 ID 不存在 → 报错，这一条不画。端点**不能**用节点文字代替ID；报错时要提示「给那个节点加 `^id`，再在这里引用它」。

## 整篇模式的额外规则

- **非节点内容静默跳过**：段落、表格、图片、callout、分隔线、列表项下隔着空行的缩进段落，以及代码块（包括 `mdmindmap` 代码块）都不出现在导图里，也不报警告。代码块整块跳过，块里的 `#`、`-` 不会被当成节点。
- **根节点**：全文恰好只有一个一级标题、而且其他节点都在它下面时，它就是根；否则用**文件名**（去掉 `.md`）作根，所有顶层节点挂在它下面。
- **联系区**：只有当文件的**最后一个块**是 `%%` … `%%` 时，它才是联系区；正文中间的 `%%` 注释块一律跳过。

## 未装插件时的样子

- Obsidian 阅读视图（整篇文件）：一份干净的大纲。`^id`、`<!-- fold -->` 和整个联系区都被隐藏，只剩 `} ` / `{ ` 前缀和色块 emoji（emoji 本身也表达了意思）。
- 实时预览、GitHub 等普通预览：联系区原样可见。
- 代码块：原文本身。

```mdmindmap
# 牛顿运动定律

- 牛顿第一定律 ^law1
  - 惯性：物体保持原有运动状态的性质
  - 质量是惯性大小的唯一量度
- 牛顿第二定律 🔴 ^law2
  - { $F=ma$
  - $a$ 由合外力决定，与 $m$ 成反比
  - } 定量关系
  - 注意：$F$ 指合外力
  - { 同向性：$a$ 与 $F_合$ 方向相同
  - 瞬时性：$a$ 与 $F_合$ 同时变化
  - 独立性：各分力独立产生加速度
  - } 三性
    - 解题先做受力分析
    - 正交分解 $F_x=ma_x$
- 牛顿第三定律 ^law3
  - { 等大、反向、共线
  - 作用在两个物体上
  - 同时产生、同时消失
  - } 与平衡力的区别
    - 平衡力作用在同一物体上 ^balance
- 应用 <!-- fold -->
  - [[连接体问题]]
  - 超重与失重
  - 传送带与板块模型

%%
law1 -.->|合力为零时的特例| law2
law3 -->|对比| balance
%%
```

## 转义与行内规则

来自「[解析器选型与语法错误提示](issues/08-parser-and-errors.md)」。

- **转义统一用反斜杠**：节点内容真的以 `{ ` 或 `} ` 开头 → 写 `\{ `、`\} `；行尾内容真的是 `^abc` → 写 `\^abc`；行尾内容真的是色块 emoji → 写 `\🔴`。反斜杠也可以转义行内 markdown 标点（如 `\*`）。
- 色块 emoji **前面有没有空格都算颜色**。
- 行内解析的优先级：`` `代码` `` 和 `$公式$` 先识别（里面的内容当原文），然后是 `[[双链]]` 和 `[文字](网址)`，最后是粗体、斜体、删除线、高亮。
- `$` 的判定：开头的 `$` 后面不能是空格，结尾的 `$` 前面不能是空格、后面不能紧跟数字（与 Obsidian 一致）。

## 诊断

- 出错时**尽量渲染**：能解析的部分照常画出，导图角落显示问题数，点开可以跳到对应行；只有一个节点都没有时才显示错误面板。
- 级别：error = 写下的东西没按本意显示；warning = 多半不是本意，但已按合理方式处理；hint = 不影响显示的建议。
- 完整清单（16 个 code，以及每条出错后导图怎么显示、改法提示要点）见「[解析器选型与语法错误提示](issues/08-parser-and-errors.md)」的答案。2026-10-03 实现时经用户同意新增第 17 个 `SUM_EMPTY`（warning：`- }` 后面没有总结文字），最新清单以 [v1 规格](../mindmap-v1-build/spec.md) §5 为准。
- `mdmindmap check` 另外用 KaTeX + mhchem 试渲染每个公式，失败报 `MATH_ERROR` 警告。
